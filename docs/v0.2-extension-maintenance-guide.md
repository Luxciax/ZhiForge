# SelectionTranslator v0.2.0 扩展、维护与实施规范

> 配套：`v0.2-product-spec.md`、`v0.2-core-architecture.md`

## 1. Platform Port

所有系统能力通过 Port 暴露，业务模块不直接依赖 Win32/Tauri 实现。

```rust
pub trait AutostartPort {
    fn is_enabled(&self) -> Result<bool, AppError>;
    fn set_enabled(&self, enabled: bool) -> Result<(), AppError>;
}

pub trait CredentialPort {
    fn load(&self, credential_id: &str) -> Result<Option<String>, AppError>;
    fn save(&self, credential_id: &str, secret: &str) -> Result<(), AppError>;
    fn delete(&self, credential_id: &str) -> Result<(), AppError>;
}
```

实现放在 `platform/`、`credentials/`。

业务 Service 依赖 Trait，不依赖 Win32 细节。

---

## 2. Tray 边界

Tray 只调用：

```text
PauseSelection
ResumeSelection
OpenSettings
SetAutostart
ExitApp
```

禁止：

- 直接访问 Hook internals；
- 直接调用 Provider Adapter；
- 直接读写 Credential；
- 直接操作 React state；
- 直接决定 Action Route。

---

## 3. Autostart 边界

调用链：

```text
Settings UI
→ SettingsService
→ AutostartPort
→ Windows implementation
```

UI 不直接写注册表或执行 shell command。

---

## 4. Settings Page Registry

Settings Shell 不写死所有页面。

```ts
export interface SettingsPageDefinition {

  title: string

  component: React.ComponentType
```

```ts
settingsRegistry.register(generalPage)
```

第三方 Fork 可注册新页面，无需修改 Settings Shell。

## 6. Data Root

业务代码禁止自行拼接 `%APPDATA%`、exe 路径和 WebView 路径。

```rust
pub trait DataRootProvider {
    fn data_root(&self) -> PathBuf;
    fn config_path(&self) -> PathBuf;
    fn logs_path(&self) -> PathBuf;
    fn webview_data_path(&self) -> PathBuf;

```

Installed / Portable 共用业务逻辑。

## 7. Settings Repository

```rust
pub trait SettingsRepository {
    fn load(&self) -> Result<AppConfig, AppError>;
    fn save(&self, config: &AppConfig) -> Result<(), AppError>;
}
```

要求：

- 原子写入；
- schema validation；
- 写失败不破坏旧配置；
- 必要时生成 `.bak`；
- 不负责 Credential。

---

## 8. Schema Version 与 Migration

所有持久化配置显式包含：

```json
{"schemaVersion": 2}
```

迁移目录：

```text
settings/migration.rs
```

流程：

```text
读取旧配置
→ 识别版本
→ parse old schema
→ migrate in memory
→ validate new schema
→ backup old file
→ atomic write
```

失败时：

- 不覆盖旧文件；
- 返回结构化错误；
- 可恢复默认配置启动。

## 9. v0.1.1 → v0.2.0 迁移

旧 localStorage：

```text
selection-translator.ai-settings.v1
```

迁移为：

```text
ProviderProfile: migrated-default-provider
ActionRoute: 四个内置动作 → migrated-default-provider
```

旧 Credential：

```text
default-provider-api-key
```

新 Credential：

```text
provider:migrated-default-provider
```

只有新 Key 保存成功后才删除旧 entry。

失败时旧 Key 必须保留。

## 11. ResultWindow 拆分

目标：

```text
ResultWindow
├─ ResultTitleBar
├─ ResultContent
├─ ResultFooter
├─ HomePanel
└─ hooks/
   ├─ useAiRequest
   ├─ useResultLifecycle
   ├─ useCredentialHydration
   └─ useSelectionAction
```

`useAiRequest`：start / cancel / chunk / done / error。

`useResultLifecycle`：blur / close / pin / Escape。

`useSelectionAction`：selection event / request state / reset。

Window Component 只组合和渲染。

## 15. Registry 通用规则

所有 Registry：

- ID 唯一；
- 重复注册失败；
- 未知 ID 返回结构化错误；
- 注册顺序不影响结果；
- Registry 不读取 UI state；
- Registry 不执行业务。

Registry 是目录，不是 Service。

---

## 16. Provider 扩展方式

新增协议，例如：

```text
ai/adapters/openai_responses.rs
```

只需要：

1. 实现 ProviderAdapter；
2. 定义 capabilities；
3. 注册；
4. 添加 tests。

不修改：

- Selection；
- Toolbar；
- ResultWindow 主结构；
- ActionService。

如果新渠道仍是 OpenAI-compatible，只新增 Provider Profile preset，不新增 Adapter。

---

## 17. Action 扩展方式

新增“代码解释”只应增加：

```text

```

Toolbar 从 Registry 自动渲染。

不修改 Toolbar 主 JSX，不修改 AI Runtime。

## 20. Anti-God-Object

以下对象同时承担两个以上业务职责时必须审查拆分：

- Window Component；
- Service；
- Adapter；
- Store；
- Registry；
- Command module。

重点看职责数。

## 21. 禁止实现方式

### 禁止 1：Provider UI 巨型 if/else

不要：

```text
if adapter === openai
if adapter === anthropic
if adapter === gemini
```

优先 capability/schema driven UI。

### 禁止 2：无限扩充 Action enum

新增 Action 使用 ActionDefinition + Registry。

### 禁止 3：继续扩大 hardcoded blacklist

新增规则进入 AppRule 层；内置 blacklist 只作为 defaults。

### 禁止 4：ResultWindow 自己 fallback

Fallback 属于 RouteService。

### 禁止 5：Tray 直接控制 Hook internals

Tray 只调用 Application Service。

### 禁止 6：Secret 回写 localStorage/config

Secret 全部进入 Credential Store。

### 禁止 7：二开直接复制整套 Service

优先扩展 Port / Adapter / Registry entry。

## 36. 每阶段开发规则

1. 先保证旧测试全绿；
2. 再添加新模块；
3. 不同时重写 UI + Selection + AI 三条主链；
4. 新 Registry / Migration 必须有测试；
5. 每阶段结束都能独立运行；
6. 不允许最后统一修；
7. 不因重构改变用户手感，除非属于明确需求。

## 43. 最终维护原则

每个模块必须能回答：

```text
它负责什么？
它不负责什么？
输入是什么？
输出是什么？
依赖谁？
谁依赖它？
如何替换？
如何测试？
```

无法回答时，说明边界不清晰。

---

## 44. 最终结论

v0.2.0 重构不能以“文件拆小了”为成功标准。

真正成功的标准是：

- 多渠道不污染 Selection；
- Action Routing 不污染 Provider Adapter；
- Tray 不污染 Hook；
- Trigger 设置不污染 AI；
- 新 Provider / Action / Settings Page 可通过注册扩展；
- 配置可持续迁移；
- Secret 始终独立；
- 用户日常划词手感保持甚至更顺。

满足这些条件后，SelectionTranslator 才真正进入可长期维护、可持续二开的产品架构。
