# SelectionTranslator v0.2.0 产品规格

> 基线：v0.1.1  
> 目标：v0.2.0  
> 平台：Windows-first  
> 产品原则：低干扰、快速、轻量、可扩展

## 1. 产品定位

SelectionTranslator 是一个低干扰 Windows Selection AI 工具。

核心体验：

> **划一下 → 点一下 → 出结果 → 继续当前工作。**

用户选中文字后，可以快速完成：

- 翻译；
- 解释；
- 总结；
- 润色；
- 后续自定义 AI 动作。

本项目不是 ChatGPT 桌面客户端、IDE、知识库、笔记软件或 OCR 全家桶。所有新增功能必须服务于“选中文字后的快速处理”。

## 3. 当前最明显的产品缺口

### 3.1 只能配置一个模型渠道

当前模型设置本质上只有一组：

```text
协议
API Base
API Key
Model
```

切换 Provider 等于覆盖原配置。

用户真正需要的是：

```text
OpenRouter
AnyRouter
Gemini Official
DeepSeek
Local Ollama
自建中转
```

同时存在，并可随时切换。

### 3.2 所有动作共用一个模型

现实使用中：

```text
翻译 → 快、便宜模型
解释 → 强推理模型
总结 → 长上下文模型
润色 → 语言能力好的模型
```

必须允许不同 Action 使用不同 Provider / Model。

### 3.3 没有托盘和暂停能力

关闭主页后应用仍在后台，但缺少：

- 系统托盘；
- 暂停划词；
- 恢复划词；
- 打开设置；
- 真正退出。

这是常驻工具的 P0 功能。

### 3.4 划词行为无法配置

当前触发策略是代码硬编码。

用户需要：

- 拖选开关；
- 双击开关；
- Shift Click 开关；
- 必须按 Ctrl / Alt / Shift；
- 临时暂停；
- 不同应用启用/禁用。

### 3.5 应用黑名单不可编辑

默认黑名单可以保留，但必须增加用户规则层。

例如用户应能手动允许 Excel，也能手动禁止 Chrome。

## 4. v0.2.0 P0 功能

### 4.1 Provider Profiles

支持多个独立渠道：

```text
OpenRouter 主线路
AnyRouter 备用
Gemini Official
Local Ollama
```

每个渠道包含：

- 名称；
- 协议；
- API Base；
- 独立 API Key；
- 默认模型；
- 启用 / 禁用；
- 拉取模型；
- 测试连接。

### 4.2 Action Routing

每个动作独立指定模型：

```text
翻译 → AnyRouter / Gemini Flash
解释 → OpenRouter / Claude Sonnet
总结 → DeepSeek / deepseek-chat
润色 → Claude Official / Sonnet
```

后续支持 fallback：

```text
主模型 → 备用模型 1 → 备用模型 2
```

### 4.3 Tray

推荐菜单：

```text
SelectionTranslator

● 划词已开启
暂停划词
打开设置
────────────
开机启动 ✓
────────────
退出
```

### 4.4 Pause / Resume

暂停时：

- 不弹 Toolbar；
- 不做 Selection resolve；
- 不卸载整个 Hook；
- 恢复应即时生效。

### 4.5 Autostart

常驻工具必须支持开机启动，并可从设置和托盘切换。

### 4.6 Trigger Profile

用户可设置：

```text
拖选            开 / 关
双击            开 / 关
Shift Click     开 / 关
要求修饰键       None / Ctrl / Alt / Shift
拖选最小距离     默认 8px
```

高级阈值可以折叠，不应默认展示。

### 4.7 App Rules

示例：

```text
Chrome.exe        开启
WPS.exe           开启
Photoshop.exe     关闭
Explorer.exe      默认
```

优先级：

```text
用户精确规则
>
用户通配规则
>
内置默认规则
>
全局默认
```

### 4.8 Settings Center

主页升级成轻量设置中心：

```text
常规
模型
动作
划词
应用
关于
```

保持小窗口，不做大型 Dashboard。

## 5. P1 功能

v0.2.x 再做：

- 自定义 Prompt；
- Action 排序；
- Action 显隐；

- 自定义 Header；

- 快速语言切换；
- 快速模型切换；

---

## 6. P2 功能

暂不优先：

- 历史记录；
- 收藏；
- OCR；
- 截图；
- 大型聊天窗口；
- 知识库；
- 动态插件市场。

原因：这些功能很容易破坏产品“小、快、划一下就走”的核心体验。

---

## 7. Toolbar 产品要求

Toolbar 必须继续保持：

- 极小；
- 不抢焦点；
- 点击外部即消失；
- 不显示解释性开发文字；
- 动作顺序可配置；
- 后续 Action 数量变化时无需重写 Toolbar。

默认动作：

```text
翻译 | 解释 | 总结 | 润色
```

后续可增加自定义动作，但默认不把 Toolbar 堆满。

---

## 8. Result Window 产品要求

继续保持：

- 快速弹出；
- 可 Pin；
- 可 Copy；
- 可 Regenerate；
- 可 Stop；
- 可查看原文；
- 弱模型输出也尽量正常显示；
- partial stream 保留。

不要加入：

- 复杂对话历史；
- 大量二级工具栏；
- 类浏览器多标签。

---

## 9. 模型设置 UX

模型渠道页应显示 Profile，而不是协议表单本身。

推荐：

```text
OpenRouter 主线路       Claude Sonnet
AnyRouter               Gemini Flash
Local Ollama            qwen3

+ 添加渠道
```

点开某条渠道后才展示：

```text
名称
协议
API 地址
API Key
默认模型
高级设置
```

普通用户首先看到的是“渠道”，而不是“协议实现”。

## 11. 语言设置

当前优先语言 / 反向语言思路保留。

但后续语言不能仅限固定枚举。

需要允许：

- 常用下拉；
- 输入任意语言；
- Toolbar 快速切换目标语言。

默认仍建议：

```text
优先语言：简体中文
反向语言：English
```

---

## 12. Portable 产品要求

当前 portable 会在 exe 旁生成：

```text
SelectionTranslator_xxx.exe.WebView2
```

v0.2.0 推荐：

```text
SelectionTranslator/
├─ SelectionTranslator.exe
└─ Data/
   ├─ config.json
   └─ WebView2/
```

Installed 模式使用：

```text
%APPDATA%\SelectionTranslator
```

## 13. History 原则

未来如果加入历史记录：

- 默认关闭；
- 不保存 API Key；

- 常用尺寸 16 / 18 / 20px；
- Inter / system-ui；

- 清晰对齐；

## 15. v0.2.0 成功标准

用户层：

- 能保存多个渠道；
- 不同 Action 能使用不同模型；
- 能一键暂停/恢复；
- 能开机启动；
- 能修改划词触发方式；
- 能控制具体应用；
- 关闭主页后仍能从托盘找回；
- 日常划词速度和手感不比 v0.1.1 差。

产品层：

- 功能增加但主流程仍然只有“划一下 → 点一下 → 出结果”；
- Settings 功能增多但界面仍然克制；
- 高级能力不干扰普通用户；
- 不把产品做成小号 Cherry Studio。

---

## 16. 结论

v0.2.0 的目标不是简单增加更多功能，而是把 SelectionTranslator 从“手感很好的 MVP”升级成真正可以长期使用的产品。

最优先的产品路径是：

```text
多渠道
→ 动作路由
→ 托盘 / 暂停 / 自启
→ Trigger / App Rules
→ 设置中心
```

完成这条主线后，再进入自定义 Action / Prompt 等 P1 能力。
